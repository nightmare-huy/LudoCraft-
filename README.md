# LudoCraft — Кирка Лудомании

Мод для **Minecraft Java 1.21.1 / NeoForge 21.1.265+**, Java 21.
Предмет: `ludocraft:gamblers_pickaxe`. Устанавливается на клиент и сервер.

## Механика

Кирка основана на **алмазной**: 1561 прочности, скорость добычи 8,
5 урона и скорость атаки 1,2. Ремонтируется алмазами, принимает обычные
зачарования кирки. Камень и другие нерудные блоки добываются как обычно.

При добыче руды игроком сервер делает один бросок **1–100**:

| Бросок | Вероятность | Результат |
|---|---:|---|
| 1–85 | 85% | Ни предметов, ни опыта; сообщение «Лох!» |
| 86–100 | 15% | Джекпот: обычный дроп ×2, ×3, ×4 или ×5 |

Множитель выбирается отдельным равномерным броском: каждый имеет **25% внутри
джекпота**, то есть **3,75% от всех добытых руд**. Это независимые броски, а не
гарантия 15 выигрышей на каждые 100 блоков.

При джекпоте проигрывается оригинальный синтезированный звук `jackpot_777.ogg`
(три сигнала и фанфара), разлетаются цветные вращающиеся конфетти и появляются
три ванильных фейерверка. Фейерверки только визуальные: не наносят урон, не
поджигают мир и не создают ракет-сущностей. Эффекты видны ближайшим игрокам.
Звук — джингл игрового автомата, а не голосовая запись слова «777».

**Опыт при выигрыше не умножается.** Умножаются предметы, уже рассчитанные
таблицей лута, включая результат «Удачи» или «Шёлкового касания».
У «Шёлкового касания» это означает несколько блоков руды, которые можно
поставить и снова разыграть. Это намеренное следствие умножения стандартного
дропа по ТЗ, без отдельного ограничения на повторную добычу.

## Определение руды и обработка дропа

В vanilla 1.21.1 **нет `BlockTags.ORES`**. Используется NeoForge
`Tags.Blocks.ORES` (`c:ores`): обычные и глубинные руды, кварц, незерское
золото, древние обломки и модовые блоки, добавленные в этот тег.

Запасная проверка ищет отдельное слово `ore`/`ores` в registry path
(например, `tin_ore`, `ore_tin`, `ores/tin`). Namespace не проверяется.
Это намеренно точнее, чем `contains("ore")`: `spore_blossom` и `heavy_core`
не должны случайно становиться рудами. Необычно названную модовую руду
можно добавить в `c:ores` датапаком.

Обработчик `OreGambling.onBlockDrops` подписан на **`BlockDropsEvent`**:

- Работает только на сервере, только для игрока с нужной киркой и только для руды.
- Не вмешивается в уже отменённые события, другие кирки, взрывы без игрока и нерудные блоки.
- При проигрыше очищает дроп, обнуляет опыт и отменяет событие.
- При выигрыше добавляет только бонусные стаки к уже рассчитанным предметам.
  Компоненты предметов сохраняются; каждый бонусный стак ограничен `getMaxStackSize()`.
- Не вызывает повторно таблицу лута и не спавнит предметы вручную: NeoForge
  выпускает изменённый список один раз после события.
- Прочность, зачарования, скорость и возможность добычи обрабатывает стандартный `PickaxeItem`.

Проверяйте механику **в выживании**: в творческом режиме стандартного дропа
нет и этот обработчик при обычном разрушении блока не вызывается.
Другие моды, меняющие тот же дроп позднее, могут повлиять на итоговый результат.

## Получение

```mcfunction
/give @s ludocraft:gamblers_pickaxe
```

Кирка также находится во вкладке инструментов. Добавлен рецепт:

```text
золотой слиток | алмаз | золотой слиток
      —       | палка |       —
      —       | палка |       —
```

Русская и английская локализации, подсказки, модель, текстуры и звук включены.

## Сборка и запуск

Нужен **JDK 21** и доступ к серверам Gradle, Maven/NeoForge и Mojang.
Gradle Wrapper включён; отдельно устанавливать Gradle не нужно.

```bash
./gradlew build
./gradlew runClient
# отдельный сервер (при необходимости принять EULA в run/eula.txt):
./gradlew runServer
```

На Windows: `gradlew.bat build` и `gradlew.bat runClient`.
Готовый мод после успешной сборки: **`build/libs/ludocraft-1.0.0.jar`**.
Скопируйте его в `mods` клиента и сервера с указанной версией NeoForge.
Это не мод для Fabric или старого Forge.

Workflow `.github/workflows/build.yml` собирает проект на Java 21 и сохраняет
JAR как артефакт Actions после push/PR либо ручного запуска workflow.
После успешной сборки основной ветки или `arena/70f21d2d-ludocraft` он также
публикует JAR и `SHA256SUMS.txt` в **GitHub Releases** с тегом `v<mod_version>`.
Из pull request и форков релизы не публикуются. Готовые релизы не перезаписываются:
для следующего выпуска увеличьте `mod_version` в `gradle.properties` и отправьте изменения.
Если релиз этой версии уже существует, новая сборка остаётся только артефактом Actions.

## Проверки

```bash
./gradlew ruleTest
```

Эти же проверки входят в `check` и `build`. Они не требуют JUnit и перебирают
все 85 проигрышных значений и все 60 сочетаний выигрышного броска/множителя,
проверяют границы аргументов RNG и ложные совпадения названий руды.
Отдельно от Minecraft их можно запустить установленным JDK:

```bash
javac --release 21 -encoding UTF-8 -d build/rule-tests \
  src/main/java/ru/ludocraft/gameplay/GamblingRules.java \
  src/test/java/ru/ludocraft/gameplay/GamblingRulesTest.java
java -cp build/rule-tests ru.ludocraft.gameplay.GamblingRulesTest
```

**Статус проверки:** полная сборка `./gradlew build --no-daemon` на Java 21
успешно выполнена в [GitHub Actions](https://github.com/nightmare-huy/LudoCraft-/actions/runs/43545733499)
14 ноября 2026 года, исходный коммит `8188d785603b0ae411567149928bade77239ba85`.
В `build` включены проверки `ruleTest`. JSON/TOML и локальные ссылки ресурсов
также проверены отдельно. Запуск Minecraft и игровой smoke-test **ещё не выполнены**.

**[Скачать ludocraft-1.0.0.jar](https://github.com/nightmare-huy/LudoCraft-/releases/download/v1.0.0/ludocraft-1.0.0.jar)** ·
[Все релизы](https://github.com/nightmare-huy/LudoCraft-/releases).
Вход в GitHub не требуется. Поместите скачанный `.jar` в `mods`.
На странице релиза выбирайте JAR из Assets, а не архивы Source code.
Файл `SHA256SUMS.txt` содержит контрольную сумму для проверки загрузки.

### Ручной smoke-test после сборки

1. В выживании добыть камень новой киркой: обычный булыжник, без сообщений и эффектов.
2. Добывать алмазную/угольную руду: при «Лох!» не должно быть ни предметов, ни XP;
   при джекпоте — умноженный лут, обычный XP и все эффекты.
3. Повторить с глубинной рудой, кварцем, незерским золотом и древними обломками.
4. Проверить «Удачу» и «Шёлковое касание», добычу на последней единице прочности.
5. Обычной алмазной киркой проверить отсутствие азартной механики.
6. В творческом режиме проверить отсутствие выигрышей при разрушении блоков.
7. На выделенном сервере с двумя клиентами проверить запуск без client-class ошибок,
   синхронизацию эффектов и отсутствие двойного дропа.
8. Проверить кирку на столе зачарований и ремонт алмазом на наковальне.

## Основные файлы

- `LudoCraft.java` — регистрации предмета, звука, частиц, вкладки и обработчика.
- `item/GamblersPickaxeItem.java` — характеристики и подсказки.
- `gameplay/OreGambling.java` — проверка руды, обработка дропа/XP и отправка эффектов.
- `gameplay/GamblingRules.java` — точная случайная логика и проверка имени блока.
- `client/` — клиентские провайдеры конфетти и фейерверков; не загружаются на сервере.
- `src/main/resources/` — все игровые ресурсы и рецепт.

Графика и звук созданы для проекта, без скачанных сторонних аудиозаписей.
Для изменения/повторной генерации ассетов (не требуется для сборки мода):

```bash
python -m venv .venv
# активируйте .venv, затем:
pip install -r tools/requirements.txt
python tools/generate_textures.py
python tools/generate_sounds.py
```

Gradle Wrapper и основа настройки взяты из официального
[NeoForge 1.21.1 MDK](https://github.com/NeoForgeMDKs/MDK-1.21.1-ModDevGradle).
