# LudoCraft — Кирка Лудомании и Карманная Лудка

Мод для **Minecraft Java 1.21.1 / NeoForge 21.1.265+**, Java 21.
Предметы: `ludocraft:gamblers_pickaxe` и `ludocraft:pocket_ludka`. Устанавливается на клиент и сервер.

## Обновление 1.2.0: вставка предметов и модовая совместимость

- Новая текстура предмета **32×32**: золотой мини-автомат «777» с рычагом.
- Входной слот больше не отбрасывает предметы из-за жёсткого ванильного списка.
  Можно вставлять обычным кликом, правой кнопкой, перетаскиванием, Shift и цифрами.
  Проверка допуска к **ставке** отделена от вставки: для неподходящего предмета
  кнопка запуска выключена, появляется предупреждение, предмет можно забрать.
  Саму Карманную Лудку класть в её входной слот нельзя.
- Перенос между инвентарём и хотбаром через Shift работает и при занятом входе.
- Клиентское закрытие/замена экрана больше не помечает меню навсегда закрытым:
  это важно для модовых оверлеев, возвращающих тот же экран. Финализация и возврат
  предметов выполняются только при закрытии **серверного** меню.
- Допуск к ставке расширен: предметы с прочностью, компонентом `minecraft:tool`,
  тегами `c:tools`, `c:armors`, `c:gems`, `c:ingots`, `minecraft:enchantable/durability`.
  Работают, например, незеритовые инструменты, луки, щиты, слитки и модовые аналоги.
- Для незнакомой экипировки сохраняются **тот же item ID и все компоненты**
  (энергия, дополнительные данные, имя, существующие чары); ремонтируется прочность.
  На 50/25% добавляются/усиливаются случайные совместимые чары; на 10% — совместимые
  максимальные чары. На 5% именная ветка джекпота также сохраняет тип модовой экипировки.
- Модовые ресурсы при выигрыше на 50/25% дают x2/x4 **того же ресурса** с теми же
  компонентами, но не больше максимального размера стака. На 10/5% — стандартные
  редкие награды Лудки. Старые специальные правила для алмазов/изумрудов сохранены.
- Зачарования выбираются из реестра мира, включая модовые. Учитывается NeoForge-хук
  `supportsEnchantment`, исключаются новые проклятия и конфликтующие чары. Существующие
  чары не понижаются. Если предмет вообще не поддерживает чар — остаётся только ремонт.

Это общая совместимость через API/теги, **не** проверенная интеграция со всеми модпаками.
Лудка не угадывает технологические уровни чужого мода по названию предмета.
Произвольные ресурсы без общих тегов нужно явно добавить датапаком; повреждаемые
предметы, которые вы не хотите разыгрывать, можно запретить.

### Настройка модпака через датапак

Теги синхронизируются штатно между сервером и клиентом; требуется установка
одинаковой версии LudoCraft с обеих сторон. После изменения датапака — `/reload`.

`data/ludocraft/tags/item/ludka_inputs.json` (замените пример ID на реальный):

```json
{
  "replace": false,
  "values": [{ "id": "your_mod:custom_crystal", "required": false }]
}
```

`data/ludocraft/tags/item/ludka_blacklist.json`:

```json
{
  "replace": false,
  "values": [{ "id": "your_mod:valuable_device", "required": false }]
}
```

Blacklist приоритетнее разрешающих тегов и автоматического определения экипировки.
Для Minecraft 1.21.1 используйте `pack.mcmeta` с `pack.pack_format: 48`.
Не добавляйте контейнеры с содержимым в ресурсный список: результат x2/x4 копирует
все компоненты добавленного предмета, включая данные, которые определяет другой мод.

## Карманная Лудка — основная механика

```mcfunction
/give @s ludocraft:pocket_ludka
```

**ПКМ** предметом в любой руке открывает `LudkaScreen`. Положите ставку в левый
слот, выберите риск и нажмите **«ДЕПНУТЬ»**. На попытку расходуется **один предмет**,
не весь стак. При проигрыше он сгорает. Выигрыш заберите справа.

Принимаются ванильные железные/алмазные мечи, кирки, топоры, лопаты, мотыги,
шлемы, нагрудники, поножи, ботинки, а также алмазы и изумруды.
С версии 1.2.0 также принимается модовая экипировка и ресурсы из общих тегов
(см. выше). Неподходящие ставки не расходуются. Для перечисленных ванильных
железных/алмазных апгрейдов награда по-прежнему создаётся заново: старые повреждения,
имя и чары не переносятся. Для остальной, в том числе модовой экипировки, компоненты
сохраняются, а чары улучшаются без конфликтов.

| Риск | Экипировка | Алмаз / изумруд |
|---|---|---|
| **50% · x2** | Железо → алмаз; алмаз → незерит того же типа | Алмаз → 2 алмаза; изумруд → 1 алмаз |
| **25% · x4** | Железо → незерит; алмаз → незерит со случайным подходящим зачарованием | 4 алмаза |
| **10% · x10** | Незерит того же типа с набором сильных совместимых чар | Незеритовый слиток или зачарованное золотое яблоко, поровну |
| **5% · x20** | Элитры, звезда Незера, булава или золотое имя «Джекпот Лудки» + максимальные чары, по 25% внутри выигрыша | Те же четыре исхода; именной предмет — незеритовая кирка |

`x2/x4/x10/x20` обозначают **уровень риска/награды**, а не безусловное количество
выпадающей экипировки. Именная награда для экипировки сохраняет тип инструмента/брони.
Максимальные чары ограничены уровнями из реестра мира и совместимостью, без новых проклятий
(например, кирка: эффективность V, удача III, прочность III, починка I).

### Интерфейс и синхронизация

- Весь GUI, кнопки и рамки рисуются `GuiGraphics.fill`, без текстур интерфейса:
  фон `#16161d`, неоновые рамки, зелёно-красная полоса шириной 280 пикселей.
- Ширина зелёной зоны: **140 / 70 / 28 / 14 px**, ровно 50/25/10/5 процентов.
- Кнопки отправляют стандартный пакет через `handleInventoryButtonClick`;
  сервер обрабатывает `LudkaMenu.clickMenuButton`: ID **0–3** — риск, **4** — запуск.
- `DataSlot` передают риск, выпавшее число, оставшиеся тики, номер розыгрыша и
  подтверждение запроса. Номер розыгрыша отличает даже два одинаковых числа подряд.
- Сервер бросает **0…99**: ровно 100 равновероятных позиций; выигрыш при `число < шанс`.
  Шкала GUI размечена 0…100. Диапазон 0…100 включительно не используется, потому
  что 101 равновероятное значение нарушило бы точные проценты.
- Сразу после клика бегунок движется в ожидании ответа. После подтверждения сервера
  идёт **3-секундная** анимация с cubic ease-out и остановкой точно на серверном числе.
  До ответа результат не угадывается на клиенте. Resize сохраняет состояние анимации.
- Сервер **сразу** помещает награду справа, но блокирует переносы на 60 тиков.
  Клиент скрывает слот и его tooltip до окончания своей анимации и серверного таймера.
  При низком TPS блокировка может продлиться дольше трёх секунд.
- Звук после завершения: `UI_TOAST_CHALLENGE_COMPLETE` при победе, `ITEM_BREAK`
  (ванильный `entity.item.break`) при проигрыше. Звук срабатывает один раз за раунд.

### Защита предметов

Повторные/неизвестные кнопки, чужой игрок, неподходящий вход, занятый выход и
повторный запуск во время розыгрыша отклоняются сервером. Shift-click, перетаскивание,
цифровые клавиши, Q, двойной клик, обмен с левой рукой и creative-clone не позволяют
забрать награду во время розыгрыша. Выход не принимает предметы извне.

Можно закрыть GUI досрочно: оставшийся вход и **уже определённый** выигрыш возвращаются
в инвентарь (при переполнении/смерти/отключении — стандартный возврат/выброс Minecraft).
Это показывает результат досрочно, но **не** делает новый бросок, не возвращает ставку
и не позволяет ускорять розыгрыши: cooldown предмета сохраняется после закрытия.
Не ставьте ценные вещи, если не готовы их потерять.

Рецепт: три золотых слитка (сверху, слева и справа), изумруд в центре, редстоун снизу.
Предмет также находится во вкладке инструментов. Интерфейс локализован на русский и английский.

### Проверка Лудки

`./gradlew build` проверяет точные вероятности, границы и позиции анимации.
`./gradlew runGameTestServer` запускает отдельный тестовый сервер: выигрыш/проигрыш
на всех рисках, однократное списание, блокировка повторных кликов/слотов, возврат
при закрытии, защита от переполненного выхода, cooldown, повторный раунд и таблица наград.
В 1.2.0 добавлены тесты настоящих inventory-click операций (не только прямого заполнения
слотов), Shift/drag/цифр, модового инструмента с пользовательскими компонентами,
тегов ресурсов, blacklist и несовместимых чар.
Эти GameTests включены в CI **до публикации** релиза; тестовые классы и структура
не входят в распространяемый JAR.

**Результат 1.1.0:** `build runGameTestServer` успешно выполнены на Java 21
14 ноября 2026 года, коммит `3e609adfebac1bb654802f6cd8743c2b08bf0516`.
[Сборка и тесты](https://github.com/nightmare-huy/LudoCraft-/actions/runs/43550065158) ·
[Скачать ludocraft-1.1.0.jar](https://github.com/nightmare-huy/LudoCraft-/releases/download/v1.1.0/ludocraft-1.1.0.jar).
Перед установкой удалите старый JAR LudoCraft из `mods`, не оставляйте обе версии.

Ручная проверка клиента ещё нужна: открыть ПКМ в обеих руках; проверить все четыре
зелёные зоны, окончательную позицию, отсутствие tooltip справа во время анимации,
звуки, resize, два одинаковых результата подряд, shift-click, закрытие с непустым
входом/выходом и работу двух клиентов на отдельном сервере.

## Механика

Кирка основана на **алмазной**: 1561 прочности, скорость добычи 8,
5 урона и скорость атаки 1,2. Ремонтируется алмазами, принимает обычные
зачарования кирки. Камень и другие нерудные блоки добываются как обычно.

При добыче руды игроком сервер делает один бросок **1–100**:

| Бросок | Вероятность | Результат |
|---|---:|---|
| 1–85 | 85% | Ни предметов, ни опыта; сообщение «Лох!» |
| 86–100 | 15% | Джекпот: обычный дроп ×2, ×3, ×4 или ×5 |

Множитель выбирается отдельным равномерным броском: каждый имеет **25% внутри
джекпота**, то есть **3,75% от всех добытых руд**. Это независимые броски, а не
гарантия 15 выигрышей на каждые 100 блоков.

При джекпоте проигрывается оригинальный синтезированный звук `jackpot_777.ogg`
(три сигнала и фанфара), разлетаются цветные вращающиеся конфетти и появляются
три ванильных фейерверка. Фейерверки только визуальные: не наносят урон, не
поджигают мир и не создают ракет-сущностей. Эффекты видны ближайшим игрокам.
Звук — джингл игрового автомата, а не голосовая запись слова «777».

**Опыт при выигрыше не умножается.** Умножаются предметы, уже рассчитанные
таблицей лута, включая результат «Удачи» или «Шёлкового касания».
У «Шёлкового касания» это означает несколько блоков руды, которые можно
поставить и снова разыграть. Это намеренное следствие умножения стандартного
дропа по ТЗ, без отдельного ограничения на повторную добычу.

## Определение руды и обработка дропа

В vanilla 1.21.1 **нет `BlockTags.ORES`**. Используется NeoForge
`Tags.Blocks.ORES` (`c:ores`): обычные и глубинные руды, кварц, незерское
золото, древние обломки и модовые блоки, добавленные в этот тег.

Запасная проверка ищет отдельное слово `ore`/`ores` в registry path
(например, `tin_ore`, `ore_tin`, `ores/tin`). Namespace не проверяется.
Это намеренно точнее, чем `contains("ore")`: `spore_blossom` и `heavy_core`
не должны случайно становиться рудами. Необычно названную модовую руду
можно добавить в `c:ores` датапаком.

Обработчик `OreGambling.onBlockDrops` подписан на **`BlockDropsEvent`**:

- Работает только на сервере, только для игрока с нужной киркой и только для руды.
- Не вмешивается в уже отменённые события, другие кирки, взрывы без игрока и нерудные блоки.
- При проигрыше очищает дроп, обнуляет опыт и отменяет событие.
- При выигрыше добавляет только бонусные стаки к уже рассчитанным предметам.
  Компоненты предметов сохраняются; каждый бонусный стак ограничен `getMaxStackSize()`.
- Не вызывает повторно таблицу лута и не спавнит предметы вручную: NeoForge
  выпускает изменённый список один раз после события.
- Прочность, зачарования, скорость и возможность добычи обрабатывает стандартный `PickaxeItem`.

Проверяйте механику **в выживании**: в творческом режиме стандартного дропа
нет и этот обработчик при обычном разрушении блока не вызывается.
Другие моды, меняющие тот же дроп позднее, могут повлиять на итоговый результат.

## Сборка и запуск

Нужен **JDK 21** и доступ к серверам Gradle, Maven/NeoForge и Mojang.
Gradle Wrapper включён; отдельно устанавливать Gradle не нужно.

```bash
./gradlew build
./gradlew runClient
# отдельный сервер (при необходимости принять EULA в run/eula.txt):
./gradlew runServer
```

На Windows: `gradlew.bat build` и `gradlew.bat runClient`.
Готовый мод после успешной сборки: **`build/libs/ludocraft-1.2.0.jar`**.
Скопируйте его в `mods` клиента и сервера с указанной версией NeoForge.
Это не мод для Fabric или старого Forge.

Workflow `.github/workflows/build.yml` собирает проект на Java 21 и сохраняет
JAR как артефакт Actions после push/PR либо ручного запуска workflow.
После успешной сборки основной ветки или `arena/70f21d2d-ludocraft` он также
публикует JAR и `SHA256SUMS.txt` в **GitHub Releases** с тегом `v<mod_version>`.
Из pull request и форков релизы не публикуются. Готовые релизы не перезаписываются:
для следующего выпуска увеличьте `mod_version` в `gradle.properties` и отправьте изменения.
Если релиз этой версии уже существует, новая сборка остаётся только артефактом Actions.

```bash
./gradlew ruleTest
```

все 85 проигрышных значений и все 60 сочетаний выигрышного броска/множителя,

### Ручной smoke-test после сборки

1. В выживании добыть камень новой киркой: обычный булыжник, без сообщений и эффектов.
2. Добывать алмазную/угольную руду: при «Лох!» не должно быть ни предметов, ни XP;
   при джекпоте — умноженный лут, обычный XP и все эффекты.
3. Повторить с глубинной рудой, кварцем, незерским золотом и древними обломками.
4. Проверить «Удачу» и «Шёлковое касание», добычу на последней единице прочности.
5. Обычной алмазной киркой проверить отсутствие азартной механики.
6. В творческом режиме проверить отсутствие выигрышей при разрушении блоков.
7. На выделенном сервере с двумя клиентами проверить запуск без client-class ошибок,
   синхронизацию эффектов и отсутствие двойного дропа.
8. Проверить кирку на столе зачарований и ремонт алмазом на наковальне.

## Основные файлы

- `LudoCraft.java` — регистрации предмета, звука, частиц, вкладки и обработчика.
- `item/GamblersPickaxeItem.java` — характеристики и подсказки.
- `gameplay/OreGambling.java` — проверка руды, обработка дропа/XP и отправка эффектов.
- `gameplay/GamblingRules.java` — точная случайная логика и проверка имени блока.
- `client/` — клиентские провайдеры конфетти и фейерверков; не загружаются на сервере.
- `src/main/resources/` — все игровые ресурсы и рецепт.

Графика и звук созданы для проекта, без скачанных сторонних аудиозаписей.
Для изменения/повторной генерации ассетов (не требуется для сборки мода):

```bash
python -m venv .venv
# активируйте .venv, затем:
pip install -r tools/requirements.txt
python tools/generate_textures.py
python tools/generate_sounds.py
```

[NeoForge 1.21.1 MDK](https://github.com/NeoForgeMDKs/MDK-1.21.1-ModDevGradle).
