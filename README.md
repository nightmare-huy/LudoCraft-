### Как пользоваться — выбор цели сохранён из 1.3.0

```mcfunction
/give @s ludocraft:pocket_ludka
```

1. ПКМ Карманной Лудкой в любой руке открывает меню.
2. Положите ставку слева: теперь допускаются **все обычные типы предметов** —
   земля, растения, еда, ресурсы, инструменты, броня, предметы установленных модов.
3. Нажмите **«Выбрать награду»**. В каталоге есть поиск по переведённому названию
   или `mod:item_id`, фильтры редкости, страницы и прокрутка колёсиком.
4. Выберите конкретный предмет. Его изображение в центре меню — только превью,
   не третий инвентарный слот. Наведите курсор, чтобы увидеть оценку и редкость.
5. Посмотрите подтверждённый сервером шанс и нажмите **«ДЕПНУТЬ»**.
6. Через трёхсекундную рулетку заберите выигрыш справа — **ровно один выбранный
   предмет в стандартном состоянии**. При проигрыше ставка сгорает.

За попытку расходуется **ОДИН** предмет, не весь стак. Прежние кнопки 50/25/10/5%
и случайные таблицы наград заменены выбором цели. Каталог не требует JEI/REI.

### Ценность, редкость и вероятность

Оценки — условные единицы игрового баланса, а не деньги и не просто цвет имени.
Они не описывают гарантированную стоимость ресурсов в каждом модпаке.

| Предмет | Базовая ценность | Категория |
|---|---:|---|
| Земля / булыжник | 1 | Обычный |
| Железный слиток | 16 | Необычный |
| Алмаз | 128 | Редкий |
| Незеритовый слиток | 2048 | Эпический |
| Звезда Незера | 8192 | Легендарный |
| Элитры | 12288 | Легендарный |

Категории определяются числом: **1–7 / 8–63 / 64–511 / 512–4095 / 4096–32767**.
Цвет рамки и фильтр каталога соответствуют этой категории.

```text
шанс = min(95%, 50% × ценность одного предмета ставки / ценность цели)
```

Сервер считает в миллионных долях, округляя вниз; показываются четыре знака
после запятой. Бросок — равномерное целое **0…999999**. Выигрыш: `бросок < шанс`.
Полоса имеет шкалу 0…100%, её зелёная часть пропорциональна настоящему шансу.
При очень малых шансах она меньше пикселя — намеренно не растягивается до 1 px.

Примеры **без переоценки датапаком**:

- Земля → незеритовый слиток: **0.0244%**.
- Алмаз → незеритовый слиток: **3.1250%**.
- Незеритовый слиток → такой же слиток: **50.0000%**.
- Незеритовый слиток → земля: **95.0000%**, не гарантированные 100%.

Количество предметов в стаке **не** увеличивает шанс. Переименование не повышает
цену. Повреждённая экипировка дешевеет пропорционально оставшейся прочности,
но стоит минимум 1 единицу. Чары, энергия, содержимое контейнеров и прочие
нестандартные компоненты ставки не дают дополнительной ценности.

### Моды: как работает автоматическая оценка

Каталог строится из реестра всех предметов текущего мира. Приоритет оценки:
**датапак → ванильные правила → профиль модового ID → материальные `c:`-теги →
общая эвристика** (тип, прочность, базовая редкость). Для конфликтующих материальных
тегов выбирается наибольшая оценка. Для неизвестных вещей остаётся общий fallback;
чужое имя вроде `othermod:unobtainium_ingot` само по себе не включает дорогой профиль.

Профили — **ручные оценки баланса, а не расчёт рецептов**. Они не учитывают изменения
рецептов модпаком, автоматизацию и цепочки конвертации. Потолок цены **32767** сохранён:
часть самых дорогих предметов упирается в него и стоит одинаково. Для строгой прогрессии
и запрета обхода крафта используйте override-теги/blacklist. Подробнее — [таблица модов](docs/mod-support.md).

**Победа создаёт стандартный экземпляр выбранного item ID.** Чары, имя, энергия,
содержимое рюкзака и другие данные ставки в цель не переносятся. Варианты одного
ID с NBT/компонентами (например, разные зелья, зачарованные книги или заряженные
устройства) не являются отдельными строками каталога. Это предотвращает копирование
произвольных данных клиента и содержимого контейнеров.

### Настройка датапаком

Теги синхронизируются Minecraft на клиент. `pack.mcmeta` для 1.21.1:

```json
{"pack":{"pack_format":48,"description":"LudoCraft balance overrides"}}
```

Чтобы оценить модовую вещь в 8192 единицы, добавьте её в файл
`data/ludocraft/tags/item/value/8192.json` (замените пример ID реальным):

```json
{"replace":false,"values":[{"id":"your_mod:advanced_machine","required":false}]}
```

Доступны значения **1, 8, 32, 128, 512, 2048, 8192, 32767**. Явный тег
приоритетнее автооценки. Если предмет попал в несколько тегов, выбирается максимальный.
В моде изначально задана оценка 512 для Кирки Лудомании; остальные override-теги пустые.

Чтобы запретить вещь и как ставку, и как награду:
`data/ludocraft/tags/item/ludka_blacklist.json`:

```json
{"replace":false,"values":[{"id":"your_mod:admin_device","required":false}]}
```

По умолчанию исключены воздух, сама Карманная Лудка и административные/технические
предметы: командные блоки, barrier, light, structure block/void, jigsaw, debug stick,
command-block minecart, spawner и trial spawner. В 1.4.0 добавлены optional-ID для
creative/debug-объектов AE2/Mekanism/Ender IO и Ender IO conduit/loot capacitor,
которым нужны индивидуальные компоненты. Технический blacklist можно заменить
датапаком; пустой стек и сама Карманная Лудка всё равно не допускаются. Выключенные
feature flags также учитываются. Старый тег `ludka_inputs` больше **не нужен**.

После изменения — `/reload`, затем заново откройте каталог. Новые предметы модов
появятся после установки модов на обе стороны и перезапуска игры/сервера.

### Серверная безопасность и анимация

- Выбор отправляет только ID меню и `ResourceLocation` предмета; сервер проверяет
  владельца, открытое меню, реестр, blacklist, feature flags и отсутствие активного спина.
- Запуск по-прежнему идёт через `clickMenuButton`, ID **4**. Старые ID риска 0–3
  отклоняются. Клиент не задаёт вероятность, награду, цену или результат.
- Перед списанием сервер заново оценивает ставку и цель. Стоимость и шанс передаются
  клиенту `DataSlot`; большие ID и числа передаются двумя 16-битными частями.
- После старта шанс и результат фиксируются. Даже если ставка была последней в
  слоте, зелёная зона не исчезает и победа не превращается в проигрыш.
- Награда появляется справа сразу на сервере, но слот скрыт и заблокирован до
  окончания 60 серверных тиков и трёхсекундной клиентской ease-out-анимации.
  При низком TPS ожидание может быть дольше. Звуки победы/поломки сохранены.
- Изменение цели, повторный старт, Shift/Q/цифры/перетаскивание/clone не обходят
  блокировку. Превью в каталоге не являются настоящими слотами и не выдают вещи.
- При досрочном закрытии остаток ставки и уже определённый выигрыш возвращаются
  стандартным способом Minecraft (при переполнении/смерти/отключении возможен выброс).
  Это может показать исход раньше анимации, но не меняет результат и не снимает cooldown.

## Кирка Лудомании (без изменений)

```mcfunction
/give @s ludocraft:gamblers_pickaxe
```

Алмазные характеристики: 1561 прочности, скорость добычи 8, урон 5, скорость атаки 1,2.
Камень и нерудные блоки добываются обычно. На руде: **85% — без предметов и XP**,
**15% — обычный дроп x2/x3/x4/x5**, множители равновероятны. Выигрыш сопровождается
звуком «777», конфетти и визуальными фейерверками без урона. XP при выигрыше обычный.
Удача и Шёлковое касание учитываются при расчёте стандартного дропа.

Используется `BlockDropsEvent` и NeoForge-тег `c:ores` (`Tags.Blocks.ORES`): vanilla
`BlockTags.ORES` в 1.21.1 отсутствует. Fallback ищет слово `ore`/`ores`, не совпадая
с `spore_blossom`/`heavy_core`. Кирку проверяйте в выживании: творческий режим не
порождает стандартный дроп. При шёлковом касании можно повторно ставить выигранную руду.

Оба предмета находятся во вкладке инструментов, имеют рецепты и RU/EN-локализацию.

## Сборка и проверки

Нужны JDK 21 и доступ к Gradle/Maven/NeoForge/Mojang. Wrapper уже включён.

```bash
./gradlew build
./gradlew runGameTestServer
./gradlew runClient
# отдельный сервер (при необходимости принять EULA в run/eula.txt):
./gradlew runServer
```

Windows: `gradlew.bat` вместо `./gradlew`. Результат: `build/libs/ludocraft-1.5.4.jar` и дополнительный ZIP профиля.
Проверка профиля отдельно: `./gradlew runEvolutionGameTestServer`.
Проверка игровых положений кирки: `./gradlew runModelSmokeClient` (нужен дисплей/OpenGL,
в CI используется Xvfb/Mesa). Создаёт отдельный мир в `run/model-smoke`, пишет PNG
в его `screenshots` и закрывается. Для повторного чистого запуска удалите только
тестовый мир `run/model-smoke/saves/ludocraft-hand-check*`.
Python-проверки модели: `python tools/check_pickaxe_model.py` с установленным Pillow.

`build` включает чистые Java-тесты: миллионы исходов, точность шансов, округление,
монотонность ценности, минимальные вероятности, границы и позиции бегунка.
GameTests проверяют земля/алмаз/незерит, выдачу именно выбранной цели, однократное
списание, клики и drag, закрытие/повторный запуск, запрет поддельных целей и чужих
меню, замороженный шанс, покрытие реестра, оценки тегов, кодек выбора и 16-битный
транспорт `DataSlot`. Новые проверки: профили модов, формы материалов, рост цен
ячеек/машин, границы, реальные общие теги и запрет переноса содержимого ставки.
Сторонние моды в тестовую среду не устанавливаются. Тестовые классы и структура не входят в распространяемый JAR.

## Публикация и файлы

GitHub Actions выполняет `build runGameTestServer runEvolutionGameTestServer` перед публикацией JAR, ZIP профиля и SHA256SUMS
в Releases. Для следующего релиза увеличьте `mod_version` в `gradle.properties`.
Существующие релизы не перезаписываются. Визуальные результаты хранятся отдельно в
`docs/previews/v<версия>/`; эта папка не подключена к Gradle и не входит в мод.

- `menu/LudkaMenu.java` — серверная транзакция, котировка и синхронизация.
- `client/LudkaScreen.java` — процедурный GUI и каталог с ghost-иконками.
- `network/SelectLudkaTarget.java` — выбор цели, без клиентских цен/наград.
- `gameplay/LudkaValues.java` — автооценка, редкости, теги переоценки.
- `gameplay/LudkaModValues.java` — независимые от модовых API профили и формы материалов.
- `gameplay/LudkaRules.java` — формула, точный бросок и анимация.
- `gameplay/OreGambling.java` — неизменённая азартная кирка.
- `tools/generate_textures.py`, `tools/generate_sounds.py` — оригинальные ассеты.

Gradle Wrapper и основа настройки взяты из официального
[NeoForge 1.21.1 MDK](https://github.com/NeoForgeMDKs/MDK-1.21.1-ModDevGradle).
